Software Design and Engineering (Enhancement One)

The artifact I selected for my Software Design and Engineering enhancement is an investment client management application that I initially constructed in my CS 410 Software Reverse Engineering course during the summer of 2026. I created this program by disassembling a compiled binary executable into assembly language, studying its memory layout and execution stack, and translating that logic back into executable C++ source code. The software functions as an investment firm portal that handles user authentication, displays client financial records, and allows updating client service selections through an interactive console menu. I chose to include this artifact in my ePortfolio because it demonstrates a complete architectural transformation from fragile, legacy code into a secure, modern software system. By removing shared memory variables and refactoring the codebase into an object-oriented design, I showcased my ability to evaluate architectural choices and build maintainable software. The enhancement significantly improved the artifact by encapsulating customer data inside dedicated domain classes (Client, AuthenticationManager, and ClientManager), separating class declarations from implementations across modular header and source files, and establishing a clean main() controller.

Through this enhancement, I demonstrated specific software engineering skills in object-oriented programming, data encapsulation, separation of concerns, and defensive input validation. In the original version, credentials and client details resided in global scope, which exposed sensitive plaintext data throughout the program's lifecycle. I improved security and system stability by isolating member variables behind private access modifiers, implementing stream manipulators for formatted table output, and writing recovery checks that handle invalid user inputs without crashing. These improvements allowed me to fully meet three course outcomes. I satisfied Course Outcome 3 by applying object-oriented design principles to reorganize loose variables into structured models while evaluating architectural trade-offs. I fulfilled Course Outcome 4 by adopting industry-standard layout practices with modular header and implementation files. Lastly, I supported Course Outcome 5 by developing a security mindset that removed global memory vulnerabilities and prevented direct administrative output exposure.

Refactoring this codebase was an iterative learning process where I gained practical experience maintaining existing software behavior while overhauling underlying architecture. A primary challenge I faced was resolving build errors caused by header dependency cycles and managing #include directives in Visual Studio. To overcome these hurdles, I carefully followed my pseudocode and planning documents from Module One, treating them as a blueprint for function boundaries and class responsibilities. I incorporated feedback by refining function naming conventions, such as renaming initializeClients() to initializeDefaultClients(), to clearly communicate operational intent and acknowledge temporary data storage until database integration. Additionally, following guidance on code organization helped me establish a clear separation of concerns without prematurely implementing data structure or database logic planned for later milestones. Overall, this process taught me the value of encapsulation and gave me confidence in refactoring legacy software cleanly.

Algorithms and Data Structures (Enhancement Two)

The artifact I selected for my Algorithms and Data Structures enhancement is the refactored C++ client management application originating from my reverse engineering coursework in CS 410. The initial reconstructed application relied on fixed-size memory structures, loose global variables, and hardcoded conditional branches to manage five client records. This rigid layout forced fixed memory allocation at compile time and created severe scalability bottlenecks, requiring linear scans of O(N) complexity to retrieve or update records. I selected this artifact for my ePortfolio because it highlights my ability to evaluate computational performance limitations and implement efficient data structures and search algorithms. The enhancement improved the artifact by replacing static arrays with a dynamic vector of Client objects, applying standard library sorting routines (sort()), and implementing a binary search algorithm (lower_bound()) to optimize data retrieval.

In this enhancement, I demonstrated advanced technical skills in algorithmic complexity analysis, dynamic memory management, vector manipulation, and search optimization. By sorting client records alphabetically by name or numerically by account identifier with O(N log N) complexity, I established an ordered dataset that enabled binary search lookup. Replacing linear scans with binary search reduced search time complexity from O(N) linear time down to O(log N) logarithmic time, allowing lookups to scale efficiently even as the dataset grows. These improvements directly fulfilled two course outcomes. I met Course Outcome 3 by evaluating algorithmic efficiency, balancing memory usage against lookup speed, and selecting optimal algorithms to solve performance bottlenecks. I also supported Course Outcome 4 by implementing C++ standard library vectors and sorting utilities to produce an efficient, professional application that scales smoothly. Additionally, I supported Course Outcome 2 by designing structured flowcharts to communicate my algorithmic decision branches to technical peers.

Enhancing this artifact deepened my understanding of algorithm selection prerequisites and memory manipulation in C++. During development, a major challenge was resolving compiler errors related to 'const' member function qualifiers inside display methods, which restricted object access during sorting operations. Investigating and fixing these qualifier issues taught me how C++ enforces immutability across object references. I incorporated feedback by ensuring that my algorithmic enhancements remained strictly modular, focusing my changes within ClientManager.h and ClientManager.cpp while leaving data models like Client.h intact. I also acted on feedback regarding search prerequisites by embedding the numerical sorting routine (sortById()) directly prior to execution of the update operation (ChangeCustomerChoice()), guaranteeing the dataset is ordered before binary search divides the search space. All planned course outcomes for this category were fully met, reinforcing my ability to analyze Big-O time complexity and optimize real-world software performance.

Databases (Enhancement Three)

The artifact I selected for my Database enhancement is the C++ client management console application that I originally reconstructed from compiled binary executable code during my software reverse engineering coursework in August 2026. Prior to this enhancement, the program permitted users to log into a portal, view client names, and update service choices, but all data was stored temporarily in runtime memory using hardcoded variables, causing all modifications to reset upon closing. I chose to include this artifact in my ePortfolio because it demonstrates how I transformed a volatile console program into a secure, database-backed application supporting persistent storage and collaborative organizational decision-making. The enhancement significantly improved the artifact by integrating an embedded SQLite database (investment_portal.db) that automatically creates relational tables upon startup, populates default records if empty, and executes full create, read, update, and delete (CRUD) operations so that client profiles and user authentication credentials remain permanently saved across application executions.

Through this enhancement, I demonstrated advanced technical skills in database architecture, schema design, SQL transaction management, C++ library integration, and defensive security programming. Moving records out of temporary memory and into a structured database allowed me to write a dedicated database manager class that establishes relational mappings, manages connection strings, and executes parameterized SQL queries that prevent injection vulnerabilities. Additionally, I adopted a defensive security mindset by moving administrative login credentials out of hardcoded strings and into a dedicated USERS table, separating user authorization from application logic. To address input validation challenges uncovered during testing, such as stream extraction accepting invalid characters and leaving trailing buffers, I implemented robust helper functions utilizing stringstream line parsing for strict numeric checks. These improvements allowed me to fully meet the course outcomes. I satisfied Course Outcome 1 by establishing persistent data storage that supports reliable collaborative environments and organizational decision-making. I fulfilled Course Outcome 4 by embedding the SQLite library within C++ and designing dedicated manager classes to handle SQL statements and transactions. Lastly, I supported Course Outcome 5 by adopting a defensive security mindset and blocking injection vectors through parameterized queries and strict input stream validation.

Reflecting on the process of enhancing this project taught me a great deal about software planning, database configuration, and iterative debugging. A primary challenge I faced was figuring out how to configure, compile, and integrate SQLite within Visual Studio, as I had not previously linked C source files directly into a C++ solution. Researching and structuring header files and build dependencies allowed me to establish a stable database connection. I incorporated feedback and guidance from earlier reviews by ensuring my code maintained modular boundaries and by expanding my implementation to support full CRUD functionality immediately rather than delaying operations. Throughout development, comprehensive testing uncovered subtle input stream vulnerabilities, such as inputs like '2a' causing double menu prints, which I resolved by refining my input validation logic. This iterative process taught me how to refine existing codebases and approach software engineering with a rigorous focus on data persistence, security, and robust error recovery.

Final Project Enhancements and Integration

For my final capstone project, I expanded and refined the fully integrated C++ investment portal application to deliver a complete, highly secure, and user-friendly software solution. Building upon my prior milestones in object-oriented architecture, efficient data structures, and relational database persistence, I implemented key stretch goal enhancements that extended the system's operational features and reinforced its defensive programming standards. Specifically, I expanded the financial service tiers from two to four options, incorporating Estate and Legacy Planning as well as Life Insurance alongside standard Brokerage and Retirement accounts, and modified the client creation, update, and display routines to handle these new choices. Additionally, I engineered a dedicated sorting algorithm, sortByServiceChoice(), which allows system users to organize client records numerically by their selected financial plan tier in addition to existing sorting options by client name and account ID. To elevate the application’s security posture and user experience, I integrated cross-platform password masking using _getch() from <conio.h> to hide credential keystrokes behind visual asterisks, implemented strict stringstream input validation to reject non-numeric menu selections, and hardened the record deletion confirmation logic to prevent accidental data loss from ambiguous user responses.

Through these final implementation steps, I demonstrated advanced technical capabilities in object-oriented software engineering, algorithmic complexity analysis, embedded database management, and defensive security design. By separating class declarations from implementation details across modular header and C++ source files, I maintained clear software boundaries while adding new features. I utilized standard library algorithms (sort) to implement sortByServiceChoice(), providing linearithmic complexity (O(N log N)) when reordering dynamic vectors before executing logarithmic (O(log N)) binary search queries. Additionally, I demonstrated expertise in database operations by maintaining relational data integrity across dynamic SQLite CRUD operations, ensuring that new records and plan updates immediately synchronized with the underlying database file (investment_portal.db) using parameterized SQL queries to prevent injection attacks.
